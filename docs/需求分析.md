## 1. 编写目的与需求依据

本文档用于明确项目的使用对象、业务流程、功能范围、数据需求和验收标准，为后续页面设计、程序开发、测试及项目管理提供依据。

根据课程项目资料，本项目以微信小程序为载体，涉及首页、我的问卷、创建问卷和搜索问卷等模块。本文将项目中的“调查问答”按调查问卷业务进行分析，不涉及知识问答或考试评分。

课程截图未明确的题型、问卷状态、权限及统计规则，均为本需求初稿提出的本期规划，不代表课程已经作出要求，也不代表系统已经实现。若后续教学资料有更明确的规定，应相应调整并记录版本变化。

## 2. 项目背景与建设目标

### 2.1 项目背景

校园活动反馈、课程意见收集和日常信息调查等场景，需要便捷地创建问卷、收集回答并查看结果。使用纸质问卷或分散的聊天消息收集信息，容易出现整理耗时、回答遗漏和后续查找困难等问题。

本项目拟开发一个微信小程序，使用户能够在统一入口中创建、查找、填写和管理问卷，完成从信息收集到结果查看的基本流程。

### 2.2 建设目标

1. 提供清晰易用的小程序界面，方便用户查找和填写问卷。
2. 支持创建包含不同题型的问卷，并设置必填规则。
3. 支持创建者查看和管理自己的问卷，了解回收情况。
4. 通过权限校验、提交校验和数据保存机制，保证基本业务正确性。
5. 使用 Git 管理需求文档及后续代码，使项目修改过程可以追溯。

## 3. 用户角色与项目范围

### 3.1 用户角色

| 角色 | 说明 | 主要权限 |
| --- | --- | --- |
| 访客 | 尚未完成身份识别的用户 | 浏览可公开访问的已发布问卷列表、搜索问卷、查看问卷内容 |
| 问卷创建者 | 完成身份识别并创建问卷的用户 | 创建、编辑草稿、发布和结束自己的问卷，查看自己的问卷结果 |
| 问卷填写者 | 完成身份识别并参与调查的用户 | 填写开放中的问卷，查看本次提交是否成功 |

创建者与填写者是业务角色，同一用户可以同时承担这两个角色。本期不单独建设后台管理员系统。

### 3.2 本期功能范围

- 首页：展示可参与的问卷及主要功能入口。
- 我的问卷：查看自己创建的问卷，管理草稿和已发布问卷。
- 创建问卷：填写基本信息，添加和维护题目，保存草稿并发布。
- 搜索问卷：按问卷标题关键词查找可参与的问卷。
- 问卷填写：填写答案，进行校验并提交。
- 结果查看：由创建者查看有效提交数量、选择题汇总及文本回答。
- 基础支撑：身份识别、访问权限校验、异常提示和数据持久化。

### 3.3 本期不包含的功能

在线支付、考试评分、复杂跳题逻辑、问卷模板市场、独立管理后台、文件上传、大规模数据分析以及 Excel 导出暂不纳入本期验收范围，可作为后续扩展方向。

## 4. 业务流程与业务规则

### 4.1 创建与发布流程

用户完成身份识别 → 进入创建问卷页面 → 填写标题和说明 → 添加题目及选项 → 保存草稿 → 校验内容 → 发布问卷 → 问卷进入首页及搜索结果。

草稿允许分次完善，发布前必须至少包含一道配置完整的题目。

### 4.2 填写与提交流程

用户浏览或搜索问卷 → 打开问卷 → 系统确认问卷仍在开放 → 用户完成身份识别并填写答案 → 校验必填项和答案格式 → 提交 → 服务端再次检查状态及重复提交情况 → 保存成功并显示完成提示。

### 4.3 结束与查看结果流程

创建者进入我的问卷 → 查看提交数量及结果 → 根据需要结束问卷 → 系统停止接收新回答，保留已有结果供创建者查看。

### 4.4 问卷状态规则

| 状态 | 是否出现在公共列表和搜索中 | 是否允许填写 | 创建者可执行的操作 |
| --- | --- | --- | --- |
| 草稿 | 否 | 否 | 编辑、保存、删除、发布 |
| 已发布 | 是 | 是，但需通过提交校验 | 查看结果、结束问卷 |
| 已结束 | 否 | 否 | 查看问卷与已有结果 |

允许的状态变化为“草稿 → 已发布 → 已结束”。本期不提供重新开放功能；已发布及已结束问卷的题目内容不可修改，以保证回答与题目版本一致。已发布及已结束问卷不提供删除功能。

### 4.5 通用规则

1. 创建问卷、管理问卷和提交回答前必须完成身份识别；具体接入方式在设计阶段确定。
2. 用户只能管理自己创建的问卷，不能读取其他创建者的回答明细或统计结果。
3. 同一用户对同一问卷仅允许成功提交一次，以系统用户标识与问卷标识共同判定。
4. 提交成功后，本期不支持修改或撤回回答。
5. 必填题必须有有效答案；选填题允许不作答。
6. 问卷已经结束时，即使填写页面此前已经打开，提交时仍应被拒绝并给出提示。
7. 页面中的按钮限制不能代替服务端校验，权限、状态和答案规则必须在服务端再次检查。

## 5. 功能需求

### 5.1 首页模块

| 编号 | 需求描述 | 验收要点 |
| --- | --- | --- |
| FR-01 | 展示项目名称、搜索入口、创建问卷入口及我的问卷入口 | 用户能够从首页进入相应页面 |
| FR-02 | 展示已发布问卷，包含标题、简要说明和发布时间，按发布时间倒序排列 | 草稿和已结束问卷不出现在公共列表中 |
| FR-03 | 点击问卷后进入问卷详情或填写页面 | 展示内容与所选问卷一致 |
| FR-04 | 支持分页加载，并显示加载中、无数据和加载失败状态 | 分页无重复项；失败时能够重试 |

### 5.2 我的问卷模块

| 编号 | 需求描述 | 验收要点 |
| --- | --- | --- |
| FR-05 | 展示当前用户创建的问卷，包括标题、状态、创建时间和有效提交数量 | 列表不包含其他用户的问卷 |
| FR-06 | 支持按草稿、已发布、已结束状态筛选 | 筛选结果与实际状态一致 |
| FR-07 | 支持继续编辑及删除自己的草稿，删除前进行确认 | 取消确认后草稿仍存在；确认后不再显示 |
| FR-08 | 支持发布有效草稿，以及结束自己的已发布问卷 | 状态变化后，公共列表和提交权限同步生效 |
| FR-09 | 提供结果查看入口 | 仅问卷创建者可以打开结果页面 |

### 5.3 创建问卷模块

| 编号 | 需求描述 | 验收要点 |
| --- | --- | --- |
| FR-10 | 支持录入问卷标题和说明 | 标题不能为空；超出长度限制时提示修改 |
| FR-11 | 支持添加单选题、多选题和文本题 | 保存并重新打开后，题型和题目内容保持一致 |
| FR-12 | 每道题可以设置题目文字、题目顺序和是否必填；选择题可以维护选项 | 必填标记、顺序和选项在填写页面正确展示 |
| FR-13 | 支持修改、删除及调整草稿中的题目顺序 | 保存后顺序和内容正确；删除题目后不保留无效配置 |
| FR-14 | 支持保存草稿，允许暂未添加题目，但必须填写有效标题 | 重新进入我的问卷后能够继续编辑 |
| FR-15 | 发布时校验题目完整性，未通过时定位或说明问题 | 无题目、题干为空或选择题选项不足时不能发布 |

本期拟采用以下输入限制，后续如有调整应同步修改页面校验、服务端校验及验收用例：

| 项目 | 规则 |
| --- | --- |
| 问卷标题 | 去除首尾空白后为1～50个字符 |
| 问卷说明 | 可选，最多500个字符 |
| 每份问卷题目数 | 发布时为1～30道 |
| 题干 | 去除首尾空白后为1～200个字符 |
| 单选题、多选题选项数 | 每题2～10个 |
| 选项文字 | 去除首尾空白后为1～100个字符，同题选项不得重复 |
| 文本题回答 | 最多500个字符；必填文本题不得仅包含空白 |

### 5.4 搜索问卷模块

| 编号 | 需求描述 | 验收要点 |
| --- | --- | --- |
| FR-16 | 支持按标题关键词进行包含匹配，搜索前去除关键词首尾空白 | 返回标题包含该关键词的已发布问卷 |
| FR-17 | 搜索结果支持分页，并按发布时间倒序排列 | 草稿、已结束问卷不会进入结果 |
| FR-18 | 空关键词显示默认已发布问卷列表；无匹配时显示空状态；失败时允许重试 | 三种情况均有明确反馈 |

### 5.5 问卷填写与提交模块

| 编号 | 需求描述 | 验收要点 |
| --- | --- | --- |
| FR-19 | 展示问卷标题、说明、题目、选项和必填标记 | 内容和创建者发布的问卷一致 |
| FR-20 | 单选题只能选一项，多选题允许选择一个或多个选项，文本题支持输入文字 | 控件行为符合题型，选填题可留空 |
| FR-21 | 提交前检查必填项和输入限制，保留已经填写的内容并提示需要修正的位置 | 校验不通过时不保存回答 |
| FR-22 | 提交过程中显示处理状态并防止连续点击；服务端保证同一用户对同一问卷只保存一份回答 | 重复请求不会生成多份有效提交 |
| FR-23 | 只有服务端确认保存成功后才显示提交成功 | 保存失败时提示失败并保留当前页面答案 |
| FR-24 | 对不存在、已结束或无权访问的问卷显示相应提示 | 不允许继续提交，且不泄露非公开内容 |

### 5.6 结果查看模块

| 编号 | 需求描述 | 验收要点 |
| --- | --- | --- |
| FR-25 | 创建者可以查看自己问卷的有效提交总数 | 数量与实际保存成功的回答份数一致 |
| FR-26 | 单选题、多选题按选项展示选择人数 | 汇总值与回答明细一致；多选题各选项人数之和可以超过提交份数 |
| FR-27 | 文本题按提交时间倒序分页展示非空回答，空回答不作为文本条目展示 | 能够逐页查看已保存的文本内容 |
| FR-28 | 没有回答时显示暂无数据；问卷结束后已有统计仍可查看 | 不出现无意义的错误或丢失历史结果 |

## 6. 数据需求

### 6.1 主要数据对象

以下为业务层面的数据需求，具体数据库字段、索引和接口格式在设计阶段确定。

| 数据对象 | 主要信息 | 关系及约束 |
| --- | --- | --- |
| 用户 | 用户唯一标识、创建时间 | 用于确认创建者与填写者身份；昵称和头像不作为核心流程必填项 |
| 问卷 | 问卷标识、创建者标识、标题、说明、状态、创建时间、更新时间、发布时间、结束时间 | 一份问卷属于一名创建者，包含多道题目 |
| 题目 | 题目标识、所属问卷标识、题型、题干、是否必填、排序值 | 一道题目只属于一份问卷 |
| 选项 | 选项标识、所属题目标识、选项文字、排序值 | 仅选择题包含选项 |
| 回答记录 | 回答记录标识、问卷标识、填写者标识、提交时间 | 同一用户与同一问卷组合最多对应一份成功提交 |
| 答案明细 | 所属回答记录、题目标识、所选选项标识或文本内容 | 选项必须属于对应题目，题目必须属于对应问卷 |

### 6.2 数据一致性要求

1. 问卷及题目保存成功后，重新打开页面应能够正确读取。
2. 一次回答中的记录和答案明细应作为一个整体保存，避免只保存部分题目。
3. 汇总统计只计算保存成功的回答，不计算校验失败或提交失败的数据。
4. 发布及提交时，以服务端读取到的有效问卷状态为准，并保证结束与提交并发时状态判断和写入一致。
5. 对重复提交请求进行唯一性控制；若网络异常导致客户端未收到确认，重试时应能够识别已有提交，不能新增重复记录。
6. 客户端传入的用户标识、题目标识及选项标识均需校验，不能直接信任。

## 7. 非功能需求

| 编号 | 类别 | 需求及验证方式 |
| --- | --- | --- |
| NFR-01 | 易用性 | 主要操作使用中文说明；必填项、加载状态、空状态及错误信息清晰；从首页可通过明确入口进入创建、搜索和我的问卷页面 |
| NFR-02 | 性能 | 在约定测试设备、正常网络、100份问卷及单份问卷100份回答的数据规模下，首页首屏、搜索首屏及提交操作的目标响应时间分别不超过3秒；记录测试环境、样本数和实际结果，作为待验证目标 |
| NFR-03 | 权限 | 服务端阻止用户编辑、结束或查看其他用户问卷结果；使用其他账号直接请求接口时也应拒绝 |
| NFR-04 | 隐私 | 核心流程不要求收集手机号、身份证号等敏感信息；回答明细及统计仅创建者可见；文档、界面及日志不得暴露身份凭据 |
| NFR-05 | 可靠性 | 提交失败时不能提示成功，网络异常应提供明确反馈；用户可重试，重试不得造成重复提交 |
| NFR-06 | 兼容性 | 在微信开发者工具及至少一台真实手机上验证核心流程，记录微信版本、设备与系统版本；检查文字遮挡、按钮溢出和页面滚动问题 |
| NFR-07 | 可维护性 | 页面、业务逻辑和数据访问职责清晰；对权限及状态规则作必要说明；需求和代码通过 Git 提交记录持续管理 |

以上性能和兼容性内容是计划验证的要求，当前尚无测试结果，不能视为已经达标。

## 8. 典型使用场景

### 8.1 创建并发布课程反馈问卷

- 前置条件：用户已完成身份识别。
- 操作：创建“课程反馈调查”，填写说明，添加一道必填单选题、一道多选题和一道选填文本题，保存草稿后发布。
- 预期结果：草稿可以重新打开；发布成功后出现在公共列表中；发布后的题目不可再修改。
- 异常情况：存在空题干或选项不足时，系统说明问题，保持草稿状态。

### 8.2 搜索并填写问卷

- 前置条件：存在标题包含“课程反馈”的已发布问卷，填写者尚未提交过。
- 操作：搜索“课程反馈”，进入问卷，填写答案并提交。
- 预期结果：必填题未作答时不能提交；答案有效且保存成功后显示完成提示。
- 异常情况：填写过程中问卷被结束时，提交被拒绝；重复点击或重试不会新增第二份回答。

### 8.3 查看调查结果并结束问卷

- 前置条件：当前用户是问卷创建者，且已有成功提交。
- 操作：进入我的问卷，查看提交数量、选项人数和文本回答，然后结束问卷。
- 预期结果：统计与已保存数据一致；结束后保留结果，问卷不再接受回答。
- 异常情况：其他用户直接访问结果入口或接口时，系统拒绝访问。

## 10. 验收标准

| 编号 | 验收场景 | 通过标准 | 对应需求 |
| --- | --- | --- | --- |
| AC-01 | 创建、保存、重新打开草稿 | 标题、说明、题型、顺序、选项和必填设置保持一致 | FR-10～FR-14 |
| AC-02 | 发布校验 | 无题目、空题干、选项不足及超过限制时不能发布；有效问卷能够发布并进入公共列表 | FR-02、FR-15 |
| AC-03 | 搜索及分页 | 关键词可查到匹配的已发布问卷；草稿和已结束问卷不可被搜索到；分页不重复 | FR-04、FR-16～FR-18 |
| AC-04 | 必填及题型校验 | 必填未完成时阻止提交；单选、多选和文本答案正确保存；伪造题目或选项被拒绝 | FR-19～FR-21、数据一致性要求 |
| AC-05 | 重复提交及网络重试 | 同一用户对同一问卷最多产生一份成功提交；未收到确认时重试不会新增记录 | FR-22～FR-23、NFR-05 |
| AC-06 | 问卷状态控制 | 草稿不可填写；结束后不可提交；在结束前打开页面也不能绕过提交时的状态检查 | FR-08、FR-24 |
| AC-07 | 权限控制 | 第二个账号不能编辑、删除、结束第一个账号的问卷，也不能读取其结果；直接调用接口同样被拒绝 | FR-05～FR-09、NFR-03 |
| AC-08 | 结果正确性 | 使用预先记录的测试答案核对提交总数、各选项人数与文本内容，结果全部一致；结束后仍可查看 | FR-25～FR-28 |
| AC-09 | 异常和空状态 | 无问卷、无匹配结果、无回答、网络失败时均显示对应提示，不出现空白死页 | FR-04、FR-18、FR-23～FR-24、FR-28 |
| AC-10 | 性能及真机验证 | 按NFR-02约定记录实测结果，满足目标；开发者工具及至少一台真机均能完成创建至结果查看的主流程 | NFR-02、NFR-06 |
| AC-11 | 项目资料管理 | 远程仓库中包含项目说明、需求分析及实际开发文件，存在可追溯的提交记录，教师能够访问提交的仓库地址 | NFR-07 |

## 11. 约束、风险与待确认事项

1. **身份及数据方案**：尚未确定采用微信云开发或自建后端。应在编码前确认身份识别方式、数据库及部署条件，并保证本文权限和一致性规则能够实现。
2. **课程范围**：需对照完整课程资料确认是否要求额外题型、分享入口、截止时间或其他功能，新增内容应先更新需求再实现。
3. **开发进度**：优先打通创建、发布、搜索、填写及结果查看流程，避免过早增加本期范围外的功能。
4. **测试条件**：微信开发者工具、真机环境和所需账号应在开发前准备；性能及兼容性结论必须以实际测试记录为准。
5. **数据内容**：课程演示使用虚构或脱敏数据，不要求填写真实敏感信息。
